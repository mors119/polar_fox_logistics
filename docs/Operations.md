# 운영 준비 문서

## 초기 실행 순서

1. Google Drive에 상위 작업 폴더 하나 생성
2. Script Properties에 `ROOT_FOLDER_ID` 저장
3. `setupSystem()` 실행
4. 생성된 입력 폴더와 4개 운영 스프레드시트 확인
5. 샘플 파일 업로드 후 `scanInputFolder()` 테스트

기존 버전에서 업데이트한 경우 `setupSystem()`을 다시 실행하고, 기존 `csv_input`과 `order_csv_input`에 남은 파일을 새 `input` 폴더로 직접 옮깁니다. 기존 폴더와 파일은 자동 삭제되지 않습니다.

## 생성되어야 하는 폴더

- `input`
- `success`
- `error`

## 생성되어야 하는 파일

- `01_메인데이터_수정금지`: 시스템 원본 시트. 일반 작업자는 수정하지 않음
- `02_상품입고_작업`: `상품등록`, `대기작업`, `완료작업`, `오류작업`
- `03_피킹_작업`: `피킹헤더`, `피킹라인`
- `04_운영대시보드_조회용`: `📊 재고현황`, `📊 주문현황`, `📊 피킹현황`, `🔗 교차검증`, `주문(완료)`. 조회만 사용

`setupSystem()` 반환값의 `files` 객체에서 각 파일의 URL과 시트 목록을 확인합니다. 기존 통합 파일은 마이그레이션 원본으로 보관되며 자동 삭제되지 않습니다.

## 파일 투입 위치

- 상품/주문 파일: `input`

첫 행의 필수 헤더를 기준으로 상품 또는 주문 흐름으로 자동 분기합니다.

최신 운영 양식과 카페24 재고 내보내기 헤더는 내부 표준 헤더로 자동 변환됩니다. 최신 주문 양식의 괄호 표기와 `배송메시지` 표기도 별도 수정 없이 처리할 수 있습니다.

카페24 재고 파일의 `재고수량`은 누적 입고량이 아닌 현재값으로 동기화됩니다. 재고 파일과 주문 파일을 같이 반영할 때는 재고 파일을 먼저 처리한 뒤 주문을 처리합니다.

`setupSystem()`은 기존 상품마스터 값을 헤더명으로 매칭해 최신 컬럼 순서로 재배치합니다. 자동화용 컬럼은 16열 이후에 보존되며 기본적으로 숨김 처리됩니다. `주문(완료)`는 대시보드 갱신 시 최신 주문 양식으로 다시 생성됩니다.

## 자주 발생하는 실수

- `sample_order.cvs`처럼 확장자를 잘못 올림
- 주문과 상품 필수 헤더가 한 파일에 섞여 유형 판별에 실패함
- `ROOT_FOLDER_ID`를 넣지 않고 `setupSystem()` 실행
- `setupSystem()` 실행 후 반환된 폴더 URL을 확인하지 않음

## 처리 결과 확인 위치

### 성공

- 상품: `상품마스터`
- 주문: `주문`, `주문상품`
- 재고 변동: `재고이력`
- 원본 입력 파일이 `success` 폴더로 이동했는지 확인

업데이트 후에는 `setupSystem()`을 한 번 다시 실행해 `success` 폴더와 `SUCCESS_FOLDER_ID`를 생성합니다. 기존에 휴지통으로 이동한 입력 파일은 자동 복원되지 않습니다.

## 수동 상품·입고 운영

1. `상품등록`에 상품을 입력하고 `validateNewProduct()`, `approveNewProduct()` 순으로 실행
2. `대기작업`에 실제입고일과 예정·실제·정상·불량 수량을 입력
3. `validateInbound()`으로 부족·초과 수량과 합계를 검수
4. `confirmInbound()`으로 재고를 반영하고 `완료작업`을 확인

`입고확정처리중` 행은 값을 수정하지 말고 `confirmInbound()`를 다시 실행합니다. `자동복구확인필요`로 `오류작업`에 이동한 경우만 현재 재고와 복구 정보를 관리자가 수동 확인합니다.

## 피킹 운영

1. `설정`에 피킹 담당자를 쉼표로 입력하고 `syncConfiguredTriggers()`를 실행
2. `createPickingInstruction()`을 실행해 카트 슬롯과 담당자를 배정
3. 작업자는 `피킹라인`의 `확인`과 X일 때 `예외사유`만 입력
4. 자동 반영을 기다리거나 `syncPickingResults()`를 수동 실행
5. `04_운영대시보드_조회용`의 `📊 피킹현황`에서 진행률, 예외 주문, 안전재고 품목을 확인

`재고관리 > 운영 대시보드 갱신`을 실행하면 `📊 재고현황`, `📊 주문현황`, `📊 피킹현황`이 함께 갱신됩니다.

`🔗 교차검증`은 주문없는 주문품목, 피킹헤더없는 피킹라인, 주문품목·상품없는 피킹라인, 상품없는 입고대기 작업을 표시합니다.

피킹 작업 중에는 행을 정렬·삭제하지 않습니다. X를 선택했다면 `재고없음`, `불량재고`, `상품불일치`, `기타` 중 예외사유를 반드시 입력합니다.

### 실패

- `오류목록`
- `파일처리이력`
- 입력 파일이 `error` 폴더로 이동했는지 확인
