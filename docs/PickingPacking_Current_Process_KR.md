# 피킹-패킹 현재 기준 프로세스 통합본

이 문서는 아래 산출물을 하나의 운영 기준으로 합친 문서다.

- `피킹운영시스템_설계명세서_v2.docx`
- `피킹시스템_운영매뉴얼.docx`
- `README (1).md.docx`
- `Apps_Script 피킹_패킹.json`
- 실제 엑셀 파일 샘플

기준 우선순위는 `설계명세서 v2.0 > Apps Script 실제 구현 > 운영 매뉴얼`이다.
운영 매뉴얼과 설치 README는 설명 문서이고, 실제 동작 기준은 `v2.0 명세`와 `Apps Script 코드`로 본다.

## 1. 기준 결론

현재 합쳐서 봐야 하는 프로세스는 다음 한 줄로 정리된다.

`주문 CSV 취입 -> 미출고 주문 묶음 생성 -> 피킹 헤더/라인 생성 -> 작업자 O/X 입력 -> 5분 주기 반영 -> 정상 차감 또는 주문 전체 취소/복원 -> 대시보드/로그 갱신`

핵심 운영 원칙은 4개다.

1. 주문은 `주문번호` 기준으로 헤더에 1건 생성한다.
2. 피킹 라인은 `품목별 주문번호` 기준으로 1:1 생성한다.
3. 작업자는 `확인` 열에 `O/X`만 입력한다.
4. 한 주문에서 `X`가 1건이라도 발생하면 그 주문은 전체 취소한다.

## 2. 실제 기준 파일 구성

현재 기준 구조는 4개 데이터 파일 + 1개 독립형 Apps Script 프로젝트다.

| 역할 | 실제 기준 파일 | 설명 |
|---|---|---|
| 상품마스터 | `상품마스터.xlsx` | 상품코드, 보관위치, 상품명, 옵션, 가용재고의 SSOT |
| 주문 원장 | `주문(완료).xlsx` | CSV 취입 대상. 피킹지시번호/주문상태/취소사유까지 관리 |
| 피킹 헤더 | `피킹(해더).xlsx` | 주문 단위 피킹 지시, 슬롯, 담당자, 상태 |
| 피킹 라인 + 콘솔 | `피킹(라인).xlsx` | 작업자가 여는 파일. 라인 시트 + 설정 + 로그 + 대시보드 포함 |
| 자동화 | `Apps_Script 피킹_패킹.json` | 독립형 Apps Script. 위 4개 파일을 ID로 연결 |

중요한 점은 `피킹(라인).xlsx`가 더 이상 단순 라인 파일이 아니라는 점이다.
실제 파일에는 아래 탭이 함께 들어 있다.

- `시트1`: 피킹 라인
- `설정`
- `재고이동로그`
- `작업로그`
- `대시보드`

즉, `운영콘솔을 피킹(라인) 파일 내부 탭으로 통합`한 `v2.0` 구조가 실제 파일과도 맞는다.

## 3. 단계별 통합 프로세스

### P0. 주문 CSV 취입

입력:

- 쇼핑몰 CSV
- 업로드 폴더

처리:

- CSV를 읽어 `주문(완료)`에 적재
- `품목별 주문번호` 기준 중복 제거
- 문자열 필드(`주문번호`, `품목별 주문번호`, `상품코드`, `우편번호`, `휴대전화`)를 문자열로 유지
- 신규 행에 기본값 기록
  - `출고완료 = 0`
  - `피킹지시번호 = 공란`
  - `주문상태 = 정상`
- 처리 완료 CSV는 `처리완료` 폴더로 이동

출력:

- `주문(완료)` 신규 주문 적재

### P1. 피킹지시 생성

대상 조건:

- `출고완료 = 0`
- `피킹지시번호 = 공란`
- `주문상태 != 취소`

처리:

- 대상 주문 중 마스터 미등록 상품코드가 있는 주문은 통째로 제외
- 하나의 실행마다 `피킹지시번호` 1개 생성
- `주문번호`별로 헤더 1행 생성
- 슬롯 번호와 담당자 배정
- 주문별 `품목수`, `총수량` 계산

출력:

- `피킹(해더)`에 주문 단위 행 생성
- 이후 `피킹(라인)` 생성
- 성공 시 마지막에만 `주문(완료)`에 `피킹지시번호` 기록

### P2. 피킹라인 생성

처리:

- `품목별 주문번호` 1건당 라인 1행 생성
- `상품코드`로 `상품마스터`를 조회해 아래 값 자동 기입
  - `보관위치`
  - `이미지`
  - `상품명`
  - `옵션`
- 초기 상태값 설정
  - `확인 = 공란`
  - `실제수량 = 공란`
  - `예외사유 = 공란`
  - `라인상태 = 미처리`

출력:

- 작업자용 피킹 라인 완성

### P3. 작업자 피킹 수행

작업자 입력 규칙:

- `O`: 정상 피킹
- `X`: 예외 발생
- `예외사유`: `재고없음`, `불량재고` 중 선택

자동 규칙:

- `O`면 `실제수량 = 필요수량`
- `X`면 `실제수량 = 0`
- 부분 피킹은 허용하지 않음

즉, 현장 입력 기준은 사실상 `확인` 열과 `예외사유` 열만 본다.

### P4. 재고 반영 및 취소 처리

실행 방식:

- 기본: 5분 주기 트리거
- 수동: 메뉴 실행

처리 순서:

1. 락 획득
2. `라인상태 = 미처리`이면서 `확인` 값이 있는 라인 탐색
3. `X`가 있는 주문을 먼저 취소 판정
4. 취소 대상이 아닌 `O` 라인만 재고 차감
5. 헤더 상태와 주문 출고완료 갱신
6. 로그 및 대시보드 갱신

핵심은 `취소를 차감보다 먼저 처리`한다는 점이다.
같은 주문에 `O`와 `X`가 같이 들어온 경우, 그 주문은 차감하지 않고 바로 취소 처리한다.

### P5. 취소 주문 조회

관리자는 취소 주문 목록에서 아래를 확인한다.

- 슬롯
- 주문번호
- 담당자
- 취소사유
- 취소일시
- 복원 수량

### P6. 지시 마감 요약

지시별로 아래 요약을 본다.

- 완료 건수
- 취소 건수
- 취소사유별 건수
- 순차감 수량

### P7. 대시보드 갱신

대시보드는 `피킹(라인)` 내부 `대시보드` 탭에서 관리한다.

주요 표시 영역:

- 대기/진행/완료/취소 KPI
- 전체 진행률
- 슬롯별 현황
- 취소 알림
- 재고 부족 목록
- 오늘 재고 변동

## 4. 상태 기준

### 헤더 상태

| 상태 | 의미 |
|---|---|
| 대기 | 아직 시작 전 |
| 진행 | 일부 라인 처리됨 |
| 완료 | 전 라인 정상 차감 완료 |
| 예외 | 주문 취소 확정 |

### 라인 상태

| 상태 | 의미 | 재고 영향 |
|---|---|---|
| 미처리 | 아직 반영 전 | 없음 |
| 차감완료 | 정상 처리 완료 | 차감 |
| 복원완료 | 취소로 차감분 복원 | 복원 |
| 취소마감 | 취소로 더 이상 작업 안 함 | 없음 |

### 주문 상태

| 상태 | 의미 |
|---|---|
| 정상 | 아직 진행 중 또는 출고 완료 |
| 취소 | 영구 재피킹 제외 |

## 5. 예외 처리 기준

현재 통합 기준에서 가장 중요한 예외 처리 규칙은 아래다.

1. 한 주문의 라인 중 `X`가 1개라도 나오면 주문 전체 취소
2. 이미 차감된 같은 주문 라인은 `재고이동로그` 기준으로 복원
3. 아직 처리 안 한 같은 주문 라인은 `취소마감`
4. 헤더 상태는 `예외`
5. 주문 시트는 `주문상태=취소`, `취소사유`, `취소일시` 기록
6. 취소된 주문은 다시 피킹 대상에 포함하지 않음

즉, `부분 출고 없음`, `주문 단위 취소`, `라인 단위 차감/복원`이 현재 기준이다.

## 6. 문서 간 차이와 통합 판단

### 유지할 내용

- `설계명세서 v2.0`의 프로세스 정의
- `운영 매뉴얼`의 현장 작업 규칙
- `README`의 설치 흐름
- `Apps Script`의 실제 함수 분리 구조

### 버릴 내용 또는 참고용으로만 둘 내용

- `재고관리.xlsx`
  - 현재 기준 파일이 아니라 구 재고 원장 형태에 가깝다.
  - 컬럼 구조가 `상품마스터.xlsx`와 다르다.
- `재고관리의 사본.xlsx`
  - 초기 프로토타입/구성 검증 흔적이다.
  - `주문 (헤더)`, `주문 (라인)` 등 현재 기준 명칭과 다르다.
  - 현재 `v2.0` 구조로 운영 기준을 잡을 때는 기준 파일로 쓰지 않는 편이 맞다.
- `피킹 (종합).xlsx`
  - 현재 프로세스 기준의 운영 파일로 보기 어렵다.
  - 헤더만 남아 있고 실제 자동화 기준 구조가 아니다.

## 7. 지금 기준으로 합친 최종 운영안

실무에서는 아래만 기준으로 잡으면 된다.

1. 관리자는 CSV를 업로드하고 `주문 취입 -> 피킹지시 생성`까지만 한다.
2. 작업자는 `피킹(라인)`의 라인 시트에서 `O/X`만 입력한다.
3. 시스템은 5분마다 `재고 반영/취소/복원/상태 갱신`을 처리한다.
4. 관리자는 `대시보드`, `취소 주문 조회`, `지시 마감 요약`으로 운영 마감한다.

## 8. 권장 후속 작업

문서와 운영 기준을 완전히 하나로 만들려면 다음 3개를 권장한다.

1. `설계명세서 v2.0` 내용을 기준으로 단일 운영 문서 1개만 남기기
2. 구 파일(`재고관리`, `재고관리의 사본`, `피킹 (종합)`)을 `legacy`로 분리하기
3. 현재 코드 저장소의 `README.md` 또는 `docs/Operations.md`에 이 통합 프로세스를 반영하기

## 9. 한 줄 결론

지금 주신 자료는 `주문(완료) + 피킹(해더) + 피킹(라인 내부 콘솔) + 상품마스터 + 독립형 Apps Script` 구조로 합치면 되고, 운영 프로세스는 `주문 단위 지시 / 라인 단위 처리 / 예외 시 주문 전체 취소`로 통일하면 된다.
