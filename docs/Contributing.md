# 기여 가이드

## 기본 원칙

- 비즈니스 로직은 기능별 JS 파일로 분리하고, 처리 흐름은 `src/Main.js` 또는 `src/Order_Main.js`에 모읍니다.
- Google Apps Script API 호출은 가능한 한 설정, 파싱, 검증, 기록 역할별 파일로 분리합니다.
- 일회성 우회 코드보다 재사용 가능한 구조를 우선합니다.
- 구조, 설정, 운영 흐름이 바뀌면 문서도 함께 수정합니다.

## NorthFox Logistics 관점의 기여 기준

- 주문, 재고, 출고, 배송 기능은 서로 다른 유스케이스로 분리합니다.
- 하나의 기능 추가 때문에 `src/Main.js`나 `src/Order_Main.js`가 과도하게 비대해지지 않도록 보조 파일로 역할을 분리합니다.
- Cafe24, 택배 API 같은 외부 연동은 설정값과 전용 파일을 통해 관리합니다.
- 시트 컬럼 구조를 바꾸면 해당 문서와 샘플 데이터도 같이 업데이트합니다.

## Pull Request 체크리스트

- `npm run format`
- `npm run lint`
- `npm run push` 전 수동 점검

## 권장 작업 순서

1. 변경할 업무 흐름이 주문, 재고, 배송 중 어디에 속하는지 먼저 정리합니다.
2. 필요한 설정값, 시트 컬럼, CSV 구조를 먼저 정의합니다.
3. 구현 후 관련 처리 파일을 최소 범위로 연결합니다.
4. 메뉴, 트리거, 초기화 코드 등 노출 지점을 최소 범위로 수정합니다.
5. 문서를 갱신합니다.
